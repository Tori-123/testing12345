# PlyHan PRD

机器可读。断言有效。超出本文范围的功能禁止实现。

---

## 1. Overview & Audience

**目标：** 用户粘贴一盘 PGN，系统指出评估掉分最大的那一手，并用三段中文说明因果。

**受众：** 刚下完一盘、对着评估条发呆的业余棋手（约 1200–1600）。评委演示走同一条路：点「载入示例」即可。

本产品不是下棋平台。棋力只来自 `POST https://chess-api.com/v1`。大模型禁止自行想棋。

---

## 2. Personas & Core User Stories

### Persona A — 高二，Rapid 1420

晚上 11:24 连输 3+2。最后一盘第 26 步推 g 兵赶马，无根 e 兵被吃后遭将杀。评估从 +1.6 掉到 -2.8。班级群没人回。他要一句指着格子说的中文，不是准确率。

### Persona B — 黑客松评委

不会记谱，只有 90 秒。必须能点「载入示例」走完全流程，看到棋盘高亮和三句人话。

### 核心用户故事（全产品仅此一条）

作为刚输完的棋手，我想粘贴这盘 PGN（或载入示例），看到掉分最大的那一手被高亮，并读到三句中文：错在哪、当时该干什么、下次先看什么——以便今晚能睡、明天还记得这一条。

禁止再写第二条主路径。

## 3. Key Features (MoSCoW)

### Must Have

唯一主轴，缺一不可：

1. 接受一段 PGN 文本（或服务端/前端内置的示例 PGN）。
2. 用棋规库拆成逐步合法 FEN。非法 PGN 直接报错，不调用引擎、不调用大模型。
3. 对每步调用 `POST https://chess-api.com/v1`，读取 `eval`。大模型不得生成着法或评估。
4. 用规则计算相邻评估跳变，只保留对走棋方最亏的 1 手。禁止输出全盘评注。
5. 将该手的 FEN、用户着法、引擎 `move`/`san`、分数差发给大模型；模型必须返回固定三字段 JSON，不得自由发挥段落。
6. 引擎失败时改走预置示例评估 JSON，大模型仍对示例局面讲解，Demo 不得空白死掉。

### Should Have

只服务上述主轴的单屏交互：

- 一个 PGN 文本框 + 一个主按钮「复盘这一手」。
- 一个「载入示例棋谱」按钮，写入文本框并允许直接提交。
- 提交后同一屏进入加载态（禁用按钮、短文案「正在找败着」）。
- 成功后同一屏展示：该手棋盘、用户着法 vs 引擎着法、三段中文。
- 失败文案一句人话（PGN 非法 / 引擎失败已降级 / 模型失败）。

### Could Have（路演可讲，本次不开发）

- 展示第 2 大掉分着。
- 从 Lichess 粘贴 URL 自动拉 PGN。
- 用户改写「我想走的那步」做对比。

### Won't Have (Out of Scope)

严禁。实现即视为验收失败：

1. 绝对不开发用户登录、OAuth、账号、权限。
2. 绝对不接入真实数据库或任何持久化。刷新页面数据归零。
3. 绝对不做人机对弈、计时、匹配、悔棋。
4. 绝对不写全盘逐步讲解、开局 RAG、MCP、实时对局提示。
5. 绝对不增加第二页路由（设置、历史、个人中心、课程）。单屏 SPA。

## 4. Acceptance Criteria (AI 专属验收底线)

### 结构化数据护栏

- 大模型输出必须是 JSON，且仅含三个字符串字段：`mistake`、`plan`、`cue`。缺字段、多余字段、非 JSON，一律视为失败，界面显示降级句，禁止把模型原文直接渲染。
- 引擎请求体必须含 `fen`。只使用返回的 `eval` 与 `move`/`san`。禁止用模型补着法。
- 后端对外只暴露一个分析接口。前端只打这一枪拿齐棋盘数据 + 三句人话。

### 体感延迟

- 禁止 WebSocket、消息队列、Service Worker、流式多段刷新架构。一次 HTTP 请求-响应。
- PGN 超过 80 半步（40 回合）必须拒绝，提示「先截到败着附近再贴」。防止逐步调引擎拖死 Demo。
- 加载态必须在点击后 200ms 内出现。全程目标 30 秒内出结果；超时显示失败/降级，禁止无限转圈。

### 断网 / 接口失败降级

- 禁止离线缓存框架。降级方式：仓库内写死一份 `sample_game.json`（PGN + 逐步 eval + 已选中的败着）。
- chess-api.com 超时、429、非 JSON：改用该示例评估，仍调用大模型讲示例局面；若大模型也失败，展示示例 JSON 里预写的三句中文。
- 评委无网时：点「载入示例」必须仍能看到棋盘 + 三句话。

## 5. Entity Flow

```
PGN文本
  -> 棋规拆谱 (FEN序列 + 每步着法)
  -> chess-api.com 逐步 eval
  -> 规则选出掉分最大的 1 手 (WorstPly)
  -> 大模型 (仅翻译 WorstPly) -> { mistake, plan, cue }
  -> 单屏渲染 (棋盘高亮 + 三句中文)
```

失败旁路：

```
引擎失败 -> sample_game.json 中的 WorstPly -> 大模型
大模型失败 -> sample_game.json 中预写的 { mistake, plan, cue }
```

实体只有这些：`PgnInput`、`FenStep`、`EngineEval`、`WorstPly`、`CoachingCopy`。不存在 User、Session、GameRecord 表。
