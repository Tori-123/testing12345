# 1.2 市场调研与方案可行性验证

选定场景：场景一 + 场景三合并为单一产品切口——**关键失误人话复盘**。

---

### 0. 认知对齐 (Understanding Check)

我们要解决的不是「做一个国际象棋训练平台」，也不是「让用户能跟 AI 下棋」。

复述后的痛点是：

业余棋手下完一盘，已经能从 Lichess / Chess.com 的评估条上看出「有一步很差」。他们卡死在下一步：**这步差在丢掉了哪个具体机会**。引擎给出 `+1.42` 和 `Nxe5 Bxe5...`，棋手能看懂「该走马」，看不懂「当时为什么必须先看这匹马」。与此同时，全盘 40 步逐步分析会造成认知过载——他们需要教练式的裁剪：只指出 1 个（最多 2 个）真正改写胜负的失误，并用中文说清因果。

所以核心问题是两件事叠在一起：

1. **定位**：哪一步才是败着（场景三）
2. **翻译**：这一步为什么坏、下次先看什么（场景一）

这是我们团队要解决的核心问题。引擎 API 负责算「哪一步掉分最多」；大模型只负责对那一个局面说人话。不做陪练、不做开局书、不做账号体系。

---

### 1. 行业背景摘要 (Market Context)

在线国际象棋已经把「能分析」做成标配。Lichess 免费给云引擎，Chess.com 用 Game Review 把每步打上 Brilliant / Blunder 标签。业余棋手并不缺算力，缺的是**复盘的最后一公里**：从「红条」走到「我能记住的一条教训」。

同时出现两股情绪：

- 自学棋手越来越多，私教贵、预约慢，晚上输完棋没有人讲。
- 引擎越来越强，界面却仍按「分析师工作站」设计：变化、深度、胜率图。对 1200–1600 段位，信息量本身就是障碍。

切入点很小，但刚好卡在「平台已经算完、人还没听懂」这个缝里。国际象棋 API（chess-api.com、Lichess 评估）把棋力变成可调用的数字；大模型第一次让「把两个候选着的分数差写成一句中文因果」变得便宜。这不是新棋力，是新教练话术层。

---

### 2. 竞品分析 (Competitor Analysis)

面对「我刚下完这盘，请只告诉我那步败着到底错在哪」，现有方案的操作链路如下。

**Lichess 电脑分析**

用户要等整盘分析跑完，看准确率百分比和评估曲线，自己去点红色着法。点进去之后仍是引擎语言：最佳着、深度、百分兵。没有人替他把 40 个点收成「就这一个」。链路痛在：等待长、信息全、因果句不存在。用户最后往往只记住「哦原来该走马」，复盘结束。

**Chess.com Game Review**

比 Lichess 更像「有旁白」：Miss、Blunder、开局名称、阶段评分。对这个微观场景仍然臃肿——它要讲完整故事（开局像 1800、残局像 900），而用户只想知道第 24 步。Coach 讲解多为英文套话（"that hung a piece"），很少落到「你推的是保护马的兵」这种带格子的因果。核心功能还绑在会员上。链路痛在：产品目标是「完整战报」，不是「一条能带走的教训」。

**本地 Stockfish / 象棋数据库 GUI**

信息密度更高：MultiPV、残局库、开局树。对刚输完 3+0 的人来说，这是把显微镜递给需要急救的人。链路痛在：工具为教练和理论家设计，认知负荷远大于问题本身。

**私教、俱乐部、班级象棋群**

这是唯一真正能说人话的方案。链路是：截图 → 发群 → 等有空的人 → 得到一句「你马没根」。致命弱点是延迟和不可得。输棋发生在 23:20，能讲棋的人在写作业或已经睡了。贵、慢、无法在情绪最高的那 5 分钟介入。

**单独把棋谱丢给通用大模型**

看似能说人话，但没有引擎约束时会发明非法着、记错谁走、把均势讲成杀王。链路痛在：语言层脱离棋力层，教错比不教更糟。

**致命弱点（针对本场景）**

传统方案要么给「全量分析报告」（太臃肿），要么给「不可得的人话」（太慢），要么给「不受引擎约束的胡话」（不智能）。没有产品把工作流收成：粘贴这盘棋 → 只看掉分最大的那一手 → 三句中文因果。竞品的失败不是棋力不够，是**不肯替用户做减法**。

### 3. 可行性验证 (Feasibility & Scope)

36 小时黑客松 Demo。下游代码由 AI 生成。核心回路必须是单屏、单向、无账号。

**绝对不应该做**

- 人机对弈、匹配、计时、悔棋、棋力等级
- Lichess / Chess.com 登录与拉取对局（OAuth、限流、联调地狱）
- 用户系统、历史记录、错题本、排行榜
- 全盘逐步讲解（40 段生成 = 超时、幻觉、超支）
- 开局书 RAG、名局检索、MCP 工具链
- 实时对局外挂提示（合规与产品定位都错）
- Maia 陪练、谜题课、残局课（那是 1.1 里没选的场景）
- 微调模型、自建引擎、爬取棋谱网站
- 多页面路由：设置页、个人中心、课程列表

**必须跑通的核心体验回路**

单点输入 → 处理 → 核心价值输出，一条直线：

1. **输入**：用户粘贴一盘 PGN（Demo 提供「载入示例棋谱」按钮，避免评委不会记谱）。
2. **处理**：后端用规则库（chess.js 一类）拆成逐步 FEN；对每步调用 `POST https://chess-api.com/v1` 取 `eval`；用规则算出评估跳变，只保留掉分最大的 1 手（平局时取前 2 手封顶，Demo 优先只展示 1 手）；把该手的 FEN、用户着法、引擎最佳着、分数差交给大模型。
3. **输出**：同一屏幕上出现：那一手的棋盘高亮 + 三段固定结构的中文：错在哪、当时该执行什么计划、下次同类形状先看哪条线索。

成功标准：评委粘贴或点示例后，不等待超过合理分析时间，能指着棋盘读懂「为什么这步是败着」。除此之外全部砍掉。

引擎限流时的降级：预置一盘已算好评估的示例 PGN（静态 JSON），保证断网或 429 时 Demo 仍能演示大模型讲解。不要在现场现写爬虫或换引擎。

### 4. 目标用户画像 (Target Persona)

晚上 11 点 24 分。省重点高二，周三刚交完数学卷子。Lichess 显示 Rapid 1420，最近 20 盘 3+2 胜率 47%。他不是校队的，班级里只有另外两个人会下棋，水平一个 1100 一个 1700。

最后一盘他执白，走意大利开局，自己觉得中局「马踩到 f5 挺好看」。第 26 步他推了 g 兵赶对方的马，对面没退马，直接吃掉他挂着的 e 兵，两步后后潜入。他以为自己在进攻。对局结束页准确率 64%，评估图在第 26 步从 +1.6 垂直掉到 -2.8。他用鼠标来回拖那根红线，点开变化是 `...Qxe3+`。他认识这些字母，组不成一句能对明天有用的话。

他把棋盘截图发到「高二 3 班摸鱼群」，配字「这步是不是该吃？」群里正在传物理答案。1700 那位已经在睡觉。他不想再开一盘——连续输四盘，手指在 New Game 上悬着又缩回来。他要的是有人指着 g4 那步说：你赶马的时候，e3 的兵没人护，先看被吃的兵再赶子。他看完这句话会关灯。明天中午还会再下一盘，但今晚他需要的不是平台，是这一句。
