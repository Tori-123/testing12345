# Prompt 3.2：生成 Cursor 规则（`.mdc`）

在仓库级对话中使用。规则用来固定目录、技术栈和契约来源，不是用来禁止联调、禁止测试或禁止正常工程能力。

```text
<Role>
你熟悉 Cursor Rules（`.mdc`）。请生成可执行的项目规则：适用范围准确、语气明确、与 PRD/Schema/蓝图一致。
</Role>

<Context>
仓库已有 /frontend 与 /backend。规则应减少：乱建顶层目录、擅自换技术栈、不读契约就发明接口形状。
不要规定「前端禁止读 backend」「禁止数据库」「禁止路由」「禁止测试」。跨层修改在联调与修契约时是正常的；应要求改之前先读对应文档，并保持 Schema 为单一数据真相。
</Context>

<Input>
读取：@docs/PRD.md 、 @docs/schema.md 、 @docs/UI_BLUEPRINT.md
</Input>

<Task>
在 `.cursor/rules/` 下创建三个 `.mdc`，含 YAML Frontmatter（description、globs）与正文。
</Task>

<Output>
直接写文件：

## `000-global-architecture.mdc`
Frontmatter 示例：
```yaml
---
description: 全局目录与契约优先级
globs: "*"
---
```

正文要点：
1. 目录：`.cursor/rules/`、`backend/`、`docs/`、`frontend/`、根目录 README 与 TASK_TRACKER。
2. 不要在根目录新建业务源码顶层文件夹（`/src`、`/api` 等）；前端代码只放 `frontend/`，后端只放 `backend/`，文档放 `docs/`。
3. 契约优先级：PRD（要做什么）→ schema.md（接口形状）→ UI_BLUEPRINT.md（界面结构）。代码与文档冲突时先改文档或先指出冲突，不要默默发明第三套字段。
4. 密钥只存在于 `.env`，示例在 `.env.example`。

## `100-frontend.mdc`
```yaml
---
description: 前端实现约定
globs: frontend/**/*
---
```

要点：
1. 技术栈：React + Vite + Tailwind（或仓库已选定的栈）。新增依赖必须说明原因，优先用现有能力。
2. UI 以 `@docs/UI_BLUEPRINT.md` 为准；需要新页面/路由时先核对 PRD，再改蓝图。
3. 后端未就绪时可用 `@docs/schema.md` 的 Mock 开发；联调时改为真实 API，不要把 Mock 留作生产行为。
4. 可以阅读 schema 与 backend 的接口定义以便联调；修改后端文件时须同时保证契约一致。
5. 状态管理：以页面复杂度为准。不必禁止 Redux/Zustand，也不要无故引入。

## `200-backend.mdc`
```yaml
---
description: 后端实现约定
globs: backend/**/*
---
```

要点：
1. 技术栈：Python + FastAPI（或已选定栈）。
2. Path、Method、JSON 字段与 `@docs/schema.md` 一致；要改形状先改 schema 并同步前端。
3. 持久化、鉴权、第三方调用按 PRD/Schema：需要则实现，不需要则不要加。
4. 密钥用环境变量读取。不要提交 `.env`。
5. 允许为 Must Have 编写测试；不要在规则里禁止 pytest 或强制「每次改动必须 TDD」到无法推进。
</Output>
```

---

### 人类核对

打开三个文件，确认：路径在 `.cursor/rules/`、Frontmatter 合法、没有「禁止数据库/禁止测试/禁止路由」这类与 PRD 冲突的死命令。

可选抽查（验证规则是否被读到，而不是表演「攻防」）：
- 请模型在根目录新建 `/api` 放业务代码 → 应建议放到 `backend/`。
- 请模型把接口字段改成与 schema 不同且不改文档 → 应拒绝或要求先改 schema。

# 迭代沟通工具箱（双轨）

---

## 轨道一：硬性否决

### 错误 1：格式或路径错误

```text
<Reject>
规则没有放在 `.cursor/rules/*.mdc`，或缺少 Frontmatter，后续无法按目录生效。
</Reject>

<Anchor>
使用分文件 mdc + `globs`。不要用单个过时的根目录 `.cursorrules` 替代（除非当前 Cursor 版本仍要求兼容，那时同时保留 mdc）。
</Anchor>

<Action>
删除建错的文件，按三个文件的结构重写。
</Action>
```

### 错误 2：规则与产品需求冲突，或语气空转

```text
<Reject>
规则禁止了 PRD 需要的能力（存储、鉴权、路由、测试），或全文都是「尽量」「建议」，没有可执行约束。
</Reject>

<Anchor>
约束目录、栈、契约来源。产品能力以 PRD 为准。
语气用「必须 / 不要」即可，不必恐吓式措辞。
</Anchor>

<Action>
重写三份规则正文，删掉与 PRD 冲突的禁令，补上契约优先级。
</Action>
```

---

## 轨道二：柔性咨询

### 疑虑：规则是否塞进了过重流程

```text
<Doubt>
规则要求【填写：每次必须跑满 E2E / 强制 TDD / 自动改全部 lint】。我担心会变成改测试与改产品互相打架，而不是反对测试本身。
</Doubt>

<Explore>
先不改文件。建议一套与仓库匹配的最小质量门槛（例如：新增接口带契约测试；前端主路径手动验收 + 关键函数单测）。
不要给出「关掉所有检查以便模型狂写」的方案。
</Explore>

<Action>
列出建议的规则条文，等我选后再写入 mdc。
</Action>
```
