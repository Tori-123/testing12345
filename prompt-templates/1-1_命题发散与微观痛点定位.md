# 阶段一（1.1-1.3）在浏览器中进行，而非 IDE

阶段一的核心任务是“Research 商业微观痛点”与“产品可行性分析”。如果把这个工作放在 Cursor 里做，会带来以下几个致命问题：

* **生态错位**：Cursor 的底层设计和系统提示词（System Prompts）是高度优化于“代码生成、文件编辑和本地上下文理解”的。虽然它能联网，但它的联网能力主要用于查阅 API 文档，而不是像具备“深度搜索 (Research Mode)”的主流大模型那样，去全网抓取竞品分析、市场趋势和目标用户痛点。

* **上下文污染 (Context Window Pollution)**：如果在 Cursor 的对话框里进行了大量关于市场调研的闲聊，这些非代码相关的 token 会严重污染 AI 的上下文。等到进入阶段二需要严格按 `@docs/PRD.md` 写代码时，AI 很容易因为前面的冗杂信息而产生幻觉。

* **角色分离原则**： **“用合适的 Agent 做合适的事” (Agent Orchestration)**。在浏览器里使用带有联网能力的 AI（比如 Kimi 的深度搜索、Perplexity、或开启 Web Browsing 的 ChatGPT/Gemini）扮演“产品经理/商业分析师”，然后在 Cursor 里使用大模型扮演“架构师/程序员”。



# Prompt 1.1：命题发散与微观痛点定位 (Decode & Diverge)

<Role>
你是一名顶尖的风险投资人与极客黑客松导师，擅长发现被忽视的商业微观痛点，并利用 AI 构建 MVP。
</Role>

<Context & Constraints>
我们是一支没有深厚代码基础的中学生团队，正在参加一场为期 36 小时的 AI 黑客松。
当前企业给出的原始命题是：【在此粘贴企业原始命题】
</Context & Constraints>

<Task> 
请不要给我宏大叙事的通用解决方案。考虑到我们受限的开发时间，请深度解构上述命题，推演出10个垂直、聚焦的“微观痛点（Micro-pain-points）”场景。
</Task>

<Output> 
严格使用 Markdown 格式输出这10个场景。每个场景作为一个独立的二级标题（例如：## 场景一：[一句话概括场景名称]），并必须包含以下结构：

- Problem Statement (痛点界定)
- 为什么传统方案失效：(解释没有大模型 AI 时，这个问题为什么难解)
- 产品方向脑暴（What to Build）
- 黑客松 MVP 匹配度：(简述在 36 小时内，如何用大模型的某一个特定能力来解决它)
- 评估每个场景中引入MCP（Model Context Protocol）和RAG（检索增强生成）技术的必要性

</Output>

# 🧰 阶段一：Prompt 1.1 迭代沟通工具箱 (双轨制 Follow-up Templates)

在面对大模型给出的 3 个微观痛点场景时，AI 很难一次性做到完美。作为团队的决策者，请问自己一个问题：“**我能看懂并确定它是错的吗？**”

如果明确知道它违背了黑客松规则，请走**轨道一（硬性否决）**；如果直觉感到方案太难或看不懂其中的概念，请走**轨道二（柔性咨询）**。

---


## 🚄 轨道一：Hard Override (硬性否决机制)

**核心逻辑**：`Reject (拒绝)` -> `Anchor (重申规则)` -> `Action (重写指令)`

针对 **Prompt 1.1**，如果遇到以下三种常见的明显错误，请直接复制对应的结构化指令，无情打回重写。

### ❌ 错误情况 1：痛点太假、太宏大 (Too Broad / Macro)

**触发时机**：AI 给出的场景是“帮助打工人缓解压力”、“帮助企业提高营销效率”这种放之四海而皆准的废话，缺乏具象场景。

**纠偏提示词**：

```text
<Reject>
你提供的这 3 个场景太宏大、太泛泛而谈了。这不像是 36 小时黑客松项目，更像是一个大型 SaaS 企业的宏大商业计划。
</Reject>

<Anchor>
请重新回到“极客”和“风险投资人”的角色。我们需要的是【微小、具体的痛点】。
例如：不要说“缓解学生压力”，而要说“解决住宿高中生熄灯后偷偷在被窝里背单词时光线太暗的问题”。痛点越垂直，越容易在 36 小时内做透。
</Anchor>

<Action>
请抛弃刚才的想法，严格保持原有的输出格式，重新为我生成 3 个微观场景。
</Action>

```

### ❌ 错误情况 2：无视开发时间与技术栈约束 (Scope Creep)

**触发时机**：AI 提出的 MVP 需要“建立用户社区”、“同步多端历史记录”、“连接企业 CRM 数据库”等明显在 36 小时内无法完成的功能。

**纠偏提示词**：

```text
<Reject>
你的 MVP 设计完全无视了我们的技术栈约束。我们没有时间去搭建复杂的关系型数据库，也没有时间做多端同步。
</Reject>

<Anchor>
请重新锚定我们的 Context：只有 36 小时，没有复杂的数据库，纯靠前端 SPA + FastAPI + 大模型。
任何需要用户长时间积累数据、或者需要复杂关联查询的功能，统统砍掉！我们要的是“即用即走（Use and Go）”的单次核心交互体验。
</Anchor>

<Action>
请在之前生成的 3 个场景中，将“黑客松 MVP 匹配度”这一部分彻底重写，极度简化解决方案，确保完全不需要复杂数据库支持就能完成。
</Action>

```

### ❌ 错误情况 3：核心武器利用不充分 (Weak AI Integration)

**触发时机**：AI 提出的方案中，大模型似乎只被用来做简单的“文本翻译”或“信息检索”，随便换个传统的规则引擎也能做，没有体现出我们指定的特定 AI 算力优势。

**纠偏提示词**：

```text
<Reject>
在这些场景的解决方案中，我们手中的“核心武器（特定的 AI 大模型特性）”存在感太弱了。这种方案随便用一个传统软件工具也能做。
</Reject>

<Anchor>
评委想看到的是我们如何**榨干**企业提供的大模型的特定算力（例如：百万字上下文处理、强情感陪伴、复杂角色扮演等）。AI 必须是这个解决方案的绝对核心，而非锦上添花的边缘工具。
</Anchor>

<Action>
请保留这 3 个痛点场景本身，但重新构思“黑客松 MVP 匹配度”模块。请明确指出，在没有该大模型特定能力的情况下，这个 MVP 为什么绝对无法实现。
</Action>

```

## 🛳️ 轨道二：Soft Consult (柔性咨询机制)

**核心逻辑**：`Doubt (表达疑虑)` -> `Explore (索要评估与平替)` -> `Decide (人类拍板，此处仅展示提问阶段)` -> `Action (暂不修改，等待指令)`

针对 **Prompt 1.1**，当 AI 提出的商业场景听起来很酷，但涉及你完全不懂的领域知识时，请使用此工具。

### ⚠️ 疑虑情况：领域知识超纲或数据获取存疑 (Domain Knowledge Gap)

**触发时机**：AI 提出了一个垂直的场景，但涉及极其专业的系统（如“打通医院 EHR 电子病历系统”、“读取汽车 OBD 接口数据”、“解析复杂的财报报表”）。你不确定在比赛现场能不能拿到这些数据，或者能不能写出相应的代码。

**咨询提示词**：

```text
<Doubt>
停一下。你在场景 [填写场景序号，如：场景二] 中提到的 MVP 方案涉及了 [填写你不懂的概念，如：打通医院电子病历数据]，我完全没有这方面的背景知识，也不确定我们在黑客松现场能否合法、免费地获取到这些测试数据。我感觉这太难落地了。
</Doubt>

<Explore>
请暂时脱离“撰写方案”的状态，切换为我的“技术与商业导师”。
基于我们“只有 36 小时、零基础、无外部企业数据接口”的客观条件，帮我客观评估这个场景的真实落地难度。
如果原方案确实不可行，请保留这个“痛点方向”，但给我提供 2 到 3 个 Workarounds”（例如：不需要真实接口，只需用户手动复制粘贴一段文本给大模型处理即可）。
请用大白话列出：
1. 原方案的风险评估。
2. 平替方案的具体玩法及优缺点。
</Explore>

<Action>
请先不要修改原输出，直接把你的风险评估和降级选项列出来，等我看完后拍板决定我们做哪一个。
</Action>

```
