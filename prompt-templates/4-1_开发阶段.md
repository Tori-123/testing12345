# Prompt 4.1：开发阶段（原子指令）

契约与任务看板已锁定后，用具体指令实现，避免「帮我把前端做好」这类无法约束范围的句子。

卡住时：回滚到上次可用状态、缩小任务、查日志与契约。不要把 Mock 当成已上线接口，也不要靠「演示时看不出来」混过验收。

---

## 可复制指令模板

把括号替换成 TASK_TRACKER 中的条目。

### A. 前端组件 / 页面

```text
任务：实现 [组件或页面名称]
依据 @docs/UI_BLUEPRINT.md 与 @docs/schema.md。
1. 在 frontend/src/ 下按现有目录习惯新增或修改文件。
2. 绑定 Schema 中的字段：[列出字段]，不要发明字段。
3. 覆盖空态、加载、成功、错误（错误文案对 schema 的 error 结构）。
4. 样式遵循蓝图与现有 Tailwind/设计规范。新增依赖前先说明理由并等确认。
5. 完成后说明如何在浏览器里验证（路由、操作步骤）。
```

### B. 后端接口

```text
任务：实现 [METHOD] [path]
1. 按 @docs/schema.md 建立 Pydantic 模型与路由，字段名与类型一致。
2. 鉴权、校验失败、资源不存在的 HTTP 状态码与错误包络与契约一致。
3. 密钥与连接串只从环境变量读取。
4. 需要持久化则按 PRD 使用既定存储，不要另起一套未在 schema 出现的资源。
5. 用 curl 或现有测试方式给出验证命令。
```

### C. 联调（Mock → 真实 API）

```text
任务：将 [页面/组件] 从 Mock 切换到真实 [METHOD] [path]
1. 请求/响应必须仍符合 @docs/schema.md。
2. 处理 loading 与错误，不要在失败时静默改回假数据冒充成功。
3. 处理 CORS 与鉴权（cookie/token）的实际配置。
4. 切换完成后删除或隔离仅开发用的 Mock 路径，避免双数据源。
```

# 迭代沟通工具箱（双轨）

---

## 轨道一：硬性否决（实现失控）

### 错误：在报错循环里持续打补丁

```text
<Stop>
停止继续在同一处叠加修改。当前修复已经引入新的语法/依赖错误。
</Stop>

<Anchor>
回到本任务开始前能运行的状态（git checkout / 撤销最后一组改动）。
用契约里的最小实现：先让请求与类型通过，再加分支。
</Anchor>

<Action>
列出将要改的文件与最小步骤，等确认后只做这一步。
</Action>
```

---

## 轨道二：柔性咨询（架构偏移）

### 疑虑：中途换栈或加重大依赖

```text
<Doubt>
你准备引入【库或模式】。这不在当前规则/蓝图里。先不要合并这类改动。
</Doubt>

<Explore>
1. 现有 React/FastAPI 能力为什么不够
2. 不换栈的实现
3. 若仍要引入：体积、维护与对契约的影响
</Explore>

<Action>
先撤销未确认的依赖，给出对比后再决定。
</Action>
```

---

## 进行中的范围纪律

1. 同一任务反复失败：缩小范围（先静态布局再接线，先假存储再换数据库），并更新 TASK_TRACKER，而不是伪造成功态。
2. 发现契约不够用：先改 `docs/schema.md` / PRD / 蓝图，再改代码。
3. 验收以 PRD 条款为准：主路径、失败路径、相关页面数据一致。
