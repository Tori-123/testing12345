进入**阶段四：开发冲刺 (The Build Phase)**，这是黑客松最残酷的战场。此时，设计图纸已锁死，物理隔离已生效，所有的交互将全部通过 **Tech Lead（学生）** 对 **AI Agent（程序员）** 的“指令对谈”完成。

在这个环节，最常见的“致死”操作是 Tech Lead **下达了模糊的指令**，导致 AI Agent 产生幻觉，进而为了修复幻觉写出更多幻觉代码。

我们需要一套**原子级开发提示词库**，通过极度具体的指令，让 AI 只能在既定框架下填空。

---

### 📝 核心开发提示词库 (Atomic Dev Prompts)

请将以下提示词整理为学生随时可复制的“指令模版”：

#### 指令 A：前端组件开发 (遵循 UI_BLUEPRINT)

```text
# 任务：开发 [组件名称]
参考 @docs/UI_BLUEPRINT.md 中的组件树，请在 frontend/src/components/ 下新建该组件。
1. 使用 Tailwind CSS 实现 [具体的视觉风格] 布局。
2. 绑定 @docs/schema.md 中的 [具体字段名称] 到组件的 props 中。
3. 严禁引入任何外部动画库，只允许使用 React useState/useEffect 和原生 Tailwind 动画类名。
4. 在开发过程中，请确保组件在 Loading 状态下能展示 skeleton 或 loading icon。

```

#### 指令 B：后端接口实现 (遵循 API Schema)

```text
# 任务：实现 [接口路径] 逻辑
请在 backend/main.py 中实现 [Method] [Endpoint] 接口。
1. 输入验证：必须严格按照 @docs/schema.md 中的 Request Schema 进行 Pydantic 建模。
2. 逻辑层：调用大模型 API 时，必须从根目录的 .env 中读取 API_KEY。
3. 输出限制：返回的 JSON 结构必须与 @docs/schema.md 中的 Response Schema 逐字对齐。
4. 纯净原则：严禁添加任何数据库连接代码或持久化操作。

```

# 🧰 阶段四：Prompt 4.0 迭代沟通工具箱 (双轨制 Follow-up Templates)

> **Tech Lead 护栏心法**：在开发阶段，AI 极易“好心办坏事”。它会主动建议你“为了代码质量，我要重构后端目录”或“为了 UI 好看，我要引入 Framer Motion”。这时候，你的角色不是“鼓励”，而是“制裁”。

当 AI 写出的代码在终端报错，或试图跳出我们定义的架构时，请使用以下工具箱进行纠偏。

## 🚄 轨道一：Hard Override (代码死锁纠偏)

#### ❌ 错误情况：AI 陷入“报错死循环” (The Infinite Error Loop)

**触发时机**：AI 修改代码后，终端出现一连串 Lint 报错或模块未找到（ModuleNotFoundError）。AI 开始疯狂尝试自我修复，却越改越乱。

**纠偏提示词**：

```text
<Stop>
停！你的修复方案导致了连锁的语法错误/依赖丢失。不要再在这个循环里折腾了！
</Stop>

<Anchor>
你现在的上下文太乱了。请回退到该任务的最原始状态（回滚最后一次修改）。
请保持功能极其简单，不要试图使用任何复杂的语法特性。只写最朴素、最基础的 React/Python 代码。
</Anchor>

<Action>
请重写该逻辑：用最原始的逻辑实现功能，摒弃所有额外的逻辑判断和复杂属性绑定。
</Action>

```

---

## 🛳️ 轨道二：Soft Consult (防止架构偏离)

#### ⚠️ 疑虑情况：AI 试图重构架构或引入新技术 (Architecture Drift)

**触发时机**：AI 提交代码时说：“我发现你的 UI 蓝图里没有状态管理，我擅自引入了 Zustand 来优化状态流。”

**咨询提示词**：

```text
<Doubt>
停一下。你刚才提到引入了 [第三方库名]，这违反了我们“零依赖/保持极简”的开发铁律。我极其担心它会破坏现有的单屏架构一致性。
</Doubt>

<Explore>
作为一个 Tech Lead，我要求系统保持绝对的简洁。
1. 为什么你认为原有的方案无法满足需求？
2. 除了引入这个库，有没有只靠 React 原生功能实现的平替方案？
3. 如果必须引入，请评估它对整个项目安装包体积和构建速度的影响。
</Explore>

<Action>
请先撤销刚才引入的新库代码，并按照我要求的“纯原生方案”重新写一遍。
</Action>

```

### 🛑 阶段四的“熔断纪律” (The Tech Lead's Rule)

在开发阶段，必须严格遵守“一小时熔断原则”：

1. **观察**：如果同一个任务（比如渲染一个卡片），AI 调整了超过 3 次代码依然报错，或者在同一个逻辑上卡顿超过 1 小时。
2. **熔断**：Tech Lead 必须**果断划掉该任务**。
3. **降级**：
* 如果是 UI 渲染失败 -> **改为硬编码的静态文本显示**。
* 如果是 API 联调报错 -> **改为直接在前端写死 Mock 数据，彻底放弃与后端接口连接**（路演演示时，用户根本看不出是假数据，只要能跑通核心交互流程即可）。



**永远不要让 AI Agent 去挑战那些它在 1 小时内搞不定的技术难关。黑客松的本质是 Demo，不是 Production。**
