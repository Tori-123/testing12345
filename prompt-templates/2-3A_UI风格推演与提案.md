# Prompt 2.3A：UI 风格推演与提案 (The Vibe Check)


<Role>
你是一名 UX/UI 创意总监。前端受限于 36 小时开发时间，必须采用单屏沉浸式工作区（Single-Screen SPA）架构。
</Role>

<Context>
请注意：本产品后续的前端代码将全部由 AI Agent 自动生成。因此，在进行视觉推演时，请务必克制炫技的冲动。任何需要引入庞大 3D 引擎、复杂动画库或繁琐路由依赖的设计，都会导致后续负责写代码的 AI 陷入包版本冲突与无限报错的泥潭。
我们需要的是“仅靠原生 Tailwind CSS 就能一次性写对”的高级感。
</Context>

<Input>
请读取项目文档库中的核心文件：@docs/PRD.md 和 @docs/schema.md
</Input>

<Task>
请不要写任何代码！你需要基于产品特性和 `@docs/schema.md` 中的 Mock 数据，向团队提供 3 种截然不同的 UI 视觉风格提案。
</Task>

<Output>
请严格使用 Markdown 格式输出这 3 个提案，每个提案必须遵循以下结构：

### 提案 [1/2/3]：[提案名称] (如：极简苹果风 / 赛博朋克风 / 沉浸式对话流)
- **视觉基调 (Vibe)**: (描述配色方案、字体感觉、整体氛围)
- **布局逻辑 (Layout)**: (核心输入区在哪里？AI 返回的 Mock 数据区在哪里？如何排版才能缓解用户的等待焦虑？)
- **为什么适合本产品**: (结合我们的 PRD 目标用户进行一句话说明)


</Output>


---

### 🛑 人类干预点 1 (决策时刻)

学生团队收到这 3 个提案后，只需要做一件事：**选！**

* **输入回复示例**：“我们选提案 2（赛博朋克风），请继续。”

# 🧰 阶段二：Prompt 2.3A 迭代沟通工具箱 (双轨制 Follow-up Templates)

在 Prompt 2.3A 这个环节，大模型很容易“设计师附体”，沉迷于炫技。

最常见的翻车点有两个：一是**无视“单屏架构”的铁律，给你设计一堆带有导航栏和侧边栏的多页面系统**；二是**提出类似于“WebGL 粒子背景”、“复杂的拖拽交互”等极易让后续负责写代码的 AI Agent 陷入“报错死循环”或“依赖地狱”的复杂特效**。

当 AI 作为创意总监吐出 3 个视觉提案后，团队需要像产品经理审查设计稿一样，用挑剔的眼光审视它们。
请问自己：“**它的页面布局是不是变复杂了？它提的这些酷炫特效，后续的 AI Agent 能不能用原生的 Tailwind CSS 一次性写对？**”

如果它设计了多个页面或风格完全不符合用户画像，请走**轨道一（硬性否决）**；如果它提出了听起来很酷，但你怀疑 AI 写代码时会疯狂报错的动画特效，请走**轨道二（柔性咨询）**。

## 🚄 轨道一：Hard Override (硬性否决机制)

**核心逻辑**：`Reject (拒绝)` -> `Anchor (重申规则)` -> `Action (重写指令)`

#### ❌ 错误情况 1：违背单屏原则，引入多页面布局 (Multi-page Hallucination)

**触发时机**：AI 的布局逻辑中提到了“顶部导航栏 (Navbar)”、“侧边菜单栏 (Sidebar)”、“设置页面跳转”等明显包含多页面路由（Router）的设计。

**纠偏提示词**：

```text
<Reject>
停！你的提案违背了我们的最高前端架构原则：单屏沉浸式工作区 (Single-Screen SPA)。我们绝对没有时间让 AI 去处理复杂的路由跳转和多页面状态共享！
</Reject>

<Anchor>
请立刻砍掉所有导航栏、侧边栏和页面跳转的概念。
所有的交互必须在“同一个画面”内完成。把页面想象成一张画布，用户的输入、等待 Loading、以及最后的 AI 结果展示，只能通过局部组件的显示与隐藏来实现流转。
</Anchor>

<Action>
请摒弃多页面的思维，严格按照纯粹的单屏交互逻辑，重新为我生成这 3 个 UI 提案的【布局逻辑 (Layout)】部分。
</Action>

```

#### ❌ 错误情况 2：视觉风格与目标用户严重脱节 (Vibe Mismatch)

**触发时机**：你在 PRD 里定义的用户是“深夜焦虑的考研党”，但 AI 提案给出的风格却是“明亮活泼的马卡龙色系”；或者用户是“严谨的法律工作者”，AI 却给了“赛博朋克霓虹风”。

**纠偏提示词**：

```text
<Reject>
这些视觉基调 (Vibe) 跟我们 PRD 里的目标用户画像 (Target Persona) 完全脱节了。这种视觉风格无法引起目标用户的情感共鸣。
</Reject>

<Anchor>
请重新读取 `@docs/PRD.md` 中的目标用户画像。
设计不是为了炫技，而是为了安抚或匹配用户在那个特定微观场景下的心理状态。我们需要色彩心理学来辅助产品传递情绪价值。
</Anchor>

<Action>
请紧贴我们的目标用户画像，彻底推翻刚才的色彩和字体方案，重新为我构思 3 个能在情绪上击中用户的 UI 风格提案。
</Action>

```

## 🛳️ 轨道二：Soft Consult (柔性咨询机制)

**核心逻辑**：`Doubt (表达疑虑)` -> `Explore (索要评估与平替)` -> `Decide (人类拍板，此处仅展示提问阶段)` -> `Action (暂不修改，等待指令)`

大模型在做视觉提案时，为了凸显“高级感”，经常会建议加入复杂的动画库。如果团队盲目采纳，后期负责执行的前端 AI Agent 极容易因为版本冲突或环境配置问题，把整个项目拖入无底洞。

#### ⚠️ 疑虑情况：提出容易让 AI 写炸的前端特效 (Agent-Breaking UI Interactions)

**触发时机**：你在提案中看到了“Framer Motion 页面平滑过渡”、“WebGL 3D 粒子背景”、“复杂的拖拽式卡片交互 (Drag and Drop)”等明显超出了简单 HTML/CSS 范畴、需要引入厚重第三方库的名词。

**咨询提示词**：

```text
<Doubt>
停一下。你在提案中提到的 [填入看不懂的前端特效，如：WebGL 粒子背景 / 复杂的卡片拖拽]，考虑到后续的实际代码开发是由前端 AI Agent 自动完成的，我非常担心让 AI 去引入这种复杂的外部动画库或 3D 引擎，会导致它陷入依赖冲突、报错死循环，直接把项目搞崩。
</Doubt>

<Explore>
请你暂时脱离“创意总监”的状态，切换为我的“技术架构顾问”。
请基于我们“只有 36 小时、全靠 AI 自动生成代码、决不能卡在前端环境修 Bug 上”的极端前提，帮我评估这个特效的致死率。
如果它很容易让 AI 翻车，请立刻给我提供 2 到 3 个**极其简单、后续 AI Agent 仅靠纯粹的 Tailwind CSS 基础类名就能一次性写对**的视觉平替方案（Workarounds）。（例如：不用 WebGL，直接用 CSS 写一个简单的渐变背景动画）。
并用大白话列出每个方案的：
1. AI Agent 自动生成的成功率 (是否容易引发连环报错)
2. 视觉效果的妥协点 (Cons)
3. 稳定性 (Pros)
</Explore>

<Action>
请先不要修改提案文档，直接把这几个前端特效的平替选项列出来，等我看完后拍板决定。
</Action>

```
