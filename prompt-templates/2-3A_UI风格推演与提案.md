# Prompt 2.3A：UI 风格推演与提案

```text
<Role>
你是 UX/UI 设计师。提案要能指导后续实现，风格服务用户与任务，而不是风格秀。
</Role>

<Context>
读取产品目标与数据结构后再提案。
信息架构跟 PRD：需要多页面、导航、设置、历史列表时，提案里要有对应布局，不要强行「一切都在一屏、禁止路由」。
实现上优先 CSS/现有栈能完成的视觉；复杂动效或 3D 只有任务确实需要时再提议，并标明依赖。
</Context>

<Input>
读取：@docs/PRD.md 、 @docs/schema.md
</Input>

<Task>
不要写代码。给出 3 种可区分的视觉与布局提案，供团队选 1 个。
</Task>

<Output>
Markdown。每个提案：

### 提案 [1/2/3]：[名称]
- **视觉基调**：色彩、字体、密度、气质（说明为什么匹配 Persona）
- **信息架构与布局**：有哪些页面或区域、主导航、主操作放在哪、结果/列表放在哪
- **关键状态怎么呈现**：空态、加载、错误（不要只画理想满数据屏）
- **实现提示**：能否用现有 CSS 体系完成；若需要额外库，写明库名和原因
- **匹配度**：一句话对应 PRD 用户与主任务
</Output>
```

选定后回复示例：「选提案 2，请据此写 UI 蓝图。」

# 迭代沟通工具箱（双轨）

问自己：**布局是否覆盖 PRD 的页面与状态？风格是否像给这群用户用的？有没有为炫技引入不必要依赖？**

---

## 轨道一：硬性否决

### 错误 1：信息架构与 PRD 不符

**触发**：PRD 有多房间/设置/历史，提案却做成无法导航的单卡片；或只需一个工具屏，却堆了完整后台信息架构。

```text
<Reject>
布局没有按 PRD 的任务结构设计：该有的导航/页面没有，或不该有的站点框架堆了上去。
</Reject>

<Anchor>
先列 PRD 主故事需要的页面或区域，再谈风格。
单页工作区、多路由、侧栏，都只是手段，以任务为准。
</Anchor>

<Action>
重写三个提案的【信息架构与布局】和【关键状态】，与 PRD 对齐。
</Action>
```

### 错误 2：风格与用户脱节

```text
<Reject>
视觉基调与 Persona 的使用情境冲突（例如严肃专业工具用了娱乐向霓虹，或夜间场景用了刺眼高饱和）。
</Reject>

<Anchor>
重读 PRD 画像：使用时段、专业程度、情绪。风格用来降低认知负荷、建立信任，不是展示设计潮流。
</Anchor>

<Action>
推翻配色与字体，重出 3 个提案，每个说明如何服务该情境。
</Action>
```

---

## 轨道二：柔性咨询

### 疑虑：特效或库是否必要

**触发**：WebGL 背景、复杂拖拽、重动画库，但主任务并不依赖它们。

```text
<Doubt>
提案里的【填写特效或库】看起来不是完成主任务所必需。我想确认第一版是否该引入。
</Doubt>

<Explore>
先不改提案。说明：
1. 该效果对主任务的实际帮助
2. 用 CSS/现有组件能替代到什么程度
3. 若保留：依赖、包体积、可访问性影响
</Explore>

<Action>
给出选项，等我决定后再改提案。
</Action>
```
