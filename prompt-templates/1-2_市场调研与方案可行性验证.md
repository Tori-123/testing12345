# Prompt 1.2：市场调研与方案可行性验证

```text
<Role>
你是产品经理兼市场分析，负责切除伪需求，并把第一版范围写成可执行的结论。
你必须基于可核验的公开信息；不确定就标明「待验证」，不要编造竞品名称或数据。
</Role>

<Input>
团队从 1.1 选定的切角如下：
【粘贴切角名称、命题解读；以及已知约束】
痛点尚未分析，由本轮完成。
</Input>

<Task>
只分析这一个场景。先复述你对痛点的理解，再写分析，避免跑题。
可行性按真实产品第一版来评，而不是按「演示能不能当场跑通」来砍功能。
</Task>

<Output>
用 Markdown，层级如下：

### 0. 认知对齐
用自己的话复述：目标用户、触发情境、失败步骤、第一版应完成的闭环。
明确：这是不是我们要解决的问题。有偏差先写出来。

### 1. 行业背景
该切入点背后的趋势、规模线索或政策约束。没有可靠来源就写「待验证」，并列出建议检索词。

### 2. 竞品分析
至少分析 2 个真实存在的做法（可以是产品、工作流或通用工具）。对每个写：
- 用户怎么完成这件事（操作步骤）
- 在本场景下卡在哪（慢、贵、不准、无法协同、合规等）
禁止只用「不够智能」收尾。

### 3. 可行性与范围
- **Must**：第一版必须跑通的核心体验回路（允许必要的多步骤：输入 → 处理 → 结果 → 保存/分享等）
- **Won't**：现在明确不做，并写原因（合规、无数据、工期、非本场景）
- **开放问题**：数据源、鉴权、存储、第三方配额等必须在开发前确认的事项
不要把登录、数据库、多页面、测试默认写进 Won't。只有产品确实不需要时才排除。

### 4. 目标用户画像
写一个具体的人：角色、使用情境、当前变通办法、成功标准。
禁止「都市白领」「年轻用户」这类无法指导设计的词。
</Output>
```

---

# 迭代沟通工具箱（双轨）

问自己：**核心回路是否完整？数据从哪来？有没有把正常工程能力误判成「以后再说」？**

能确定写错了 → 轨道一；数据源或集成吃不准 → 轨道二。

---

## 轨道一：硬性否决

### 错误 1：用户画像空泛

```text
<Reject>
目标用户画像是营销套话，无法据此做信息架构和文案。
</Reject>

<Anchor>
刻画一个具体的人：职业或角色、在什么时间点、用现有工具卡在哪一步、用了我们的产品后哪件事算成功。
</Anchor>

<Action>
前三部分保持不变，只重写【4. 目标用户画像】。
</Action>
```

### 错误 2：竞品分析无法核验或隔靴搔痒

```text
<Reject>
竞品分析没有可核对的产品/做法，或弱点停留在「不够智能」。
</Reject>

<Anchor>
用真实产品或真实工作流。拆操作链路：没有我们的产品时，用户要经过哪些步骤，哪一步失败。
编造的名字删掉，改为「待验证」并给出检索方向。
</Anchor>

<Action>
重写【2. 竞品分析】，每个竞品都落到步骤级缺口。
</Action>
```

### 错误 3：范围要么膨胀，要么残缺

**触发**：Must 里塞进了多个互不依赖的产品线；或把账号、存储、错误处理、多页面等产品需要的能力一律放进 Won't。

```text
<Reject>
可行性部分没有给出「完整但最小」的第一版。范围要么同时做几条产品线，要么把交付所必需的能力删掉了。
</Reject>

<Anchor>
核心回路可以短，但必须闭环：用户能完成那件被定义的事，并且结果可保存或可复用（如果场景需要）。
砍的是旁支功能，不是基础设施。
</Anchor>

<Action>
重写【3. 可行性与范围】。Must 只保留一条主回路；Won't 写清原因；产品需要的登录/存储/路由不要无故列入 Won't。
</Action>
```

## 轨道二：柔性咨询

### 疑虑：数据源或集成可能不成立

**触发**：实时爬取、未授权的企业接口、尚未评估的微调、需要生产数据才能演示的方案。

```text
<Doubt>
【3. 可行性】里的核心回路依赖【填写：爬取 / 某企业 API / 微调 / 内部数据】。
我担心合规、稳定性和实现成本，还不能当作已定方案。
</Doubt>

<Explore>
先不要改报告。评估：
1. 原方案的合规、配额、失败模式、对工期的影响。
2. 2–3 个替代路径（官方 API、用户导入、公开数据、只读集成），写清对体验的影响。
不要默认「前端写死 JSON」作为产品方案；Mock 只用于开发阶段并行，不能代替真实数据策略。
</Explore>

<Action>
只列出选项和风险，等我选定后再改第 3 节。
</Action>
```
