# 🗺️ AI 黑客松：前置提示词与核心资产目录 (Prompt Directory)


## 🚀 阶段一：命题解构与研究 (Decode & Research)
**核心目标**：在浏览器端利用 AI 进行全网发散与商业收敛，最终产出项目的商业基石文件。

### Pro 题发散与微观痛点定位 (Decode & Diverge)
* **目的**：打破宏大叙事，让 Agent 根据企业命题生成垂直的微观痛点。
* **输入**：企业原始命题。
* **输出**：3 个微观场景提案（含场景名称、痛点界定、传统方案失效原因、MVP 匹配度）。
* **🛑 人类干预**：团队开会讨论，从备选个提案中**人为敲定 1 个**最稳妥的场景。

### Prompt 1.2：市场调研与方案可行性验证 (Research & Validate)
* **目的**：针对选定的单一场景，进行深度的可行性分析与产品定位。
* **输入**：1.1 中团队人工选中的【场景名称与痛点界定】。
* **输出**：
  - 行业背景摘要
  - 竞品分析 (传统产品的弱点)
  - Validity 验证 (绝对不做的功能 + 必须做的 1 个核心体验回路)
  - 具象的目标用户画像 (Target Persona)

### Prompt 1.3：开源资产沉淀与 README 生成 (Condense & Output)
* **目的**：将调研成果打包转化为正式的工程资产，作为后续开发的最高纲领。
* **输入**：1.1 阶段的场景名称与痛点界定 与 1.2 阶段的分析报告。
* **输出**：`README.md` 文件（包含产品名称、Slogan、核心痛点、用户画像、核心解决方案）。

## ⚙️ 阶段二：系统设计 (System Design)
**核心目标**：在 Cursor IDE 中，将商业构想降维翻译为“机器可读”的工程契约与蓝图。

### Prompt 2.1：生成精益产品需求文档 (Lean PRD)
* **目的**：制定 AI Agent 开发的军事指令，明确“做什么”和“绝对不做什么”。
* **输入**：读取项目根目录文件 `@README.md`。
* **输出**：`@docs/PRD.md` 文件
  - Overview & Audience
  - Personas & Core User Stories
  - Key Features (基于 MoSCoW 矩阵的极简核心回路)
  - Acceptance Criteria (AI 体感延迟与断网降级底线)
  - Entity Flow (数据流转概念)
* **🛑 人类干预**：严格审查 `Won't Have` 边界是否锁死，确保核心回路预估开发量可控。

### Prompt 2.2：生成前后端数据契约与 Mock 数据 (API Schema)
* **目的**：浇筑“跨海大桥的中心桥墩”，统一前后端双线并发开发的数据标准。
* **输入**：读取项目根目录文件 `@docs/PRD.md`。
* **输出**：`@docs/schema.md` 文件
  - 极简 RESTful API 路由定义 (Endpoint)
  - 扁平化的请求数据结构 (Request Schema)
  - 结构化的响应数据结构 (Response Schema)
  - 一段极其逼真且可直接用于前端渲染的 **Mock JSON 数据**
* **🛑 人类干预**：审查 JSON 结构是否足够扁平，剔除所有类似 `user_id` 的数据库绑定字段。

### Prompt 2.3A：UI 风格推演与提案 (The Vibe Check)
* **目的**：确立“单屏沉浸式工作区”的视觉基调。
* **输入**：读取 `@docs/PRD.md` 与 `@docs/schema.md`。
* **输出**：3 种不同的前端视觉风格提案（含视觉基调、布局逻辑、产品匹配度）。
* **🛑 人类干预**：团队进行视觉决策，选定其中 1 款风格。

### Prompt 2.3B：生成语义化 UI 蓝图 (The UI Blueprint)
* **目的**：用 DOM 积木树替代手绘草图，彻底消灭多模态 AI 生成前端代码时的幻觉。
* **输入**：团队选定的视觉风格 + 读取 `@docs/schema.md` 的 Mock 数据。
* **输出**：`@docs/UI_BLUEPRINT.md` 文件
  - 强制单屏架构原则
  - 全局设计规范 (Design System)
  - 核心交互状态流转 (Initial -> Loading -> Result)
  - 精确绑定了 Mock 数据字段的 **DOM 组件树映射 (Component Tree)**
* **🛑 人类干预**：核对组件树中是否混入了多页面路由（如 NavBar/Sidebar），确保数据字段与后端的 Schema 完全对齐。



## 🧱 阶段三：开发与迭代 (Build & Iterate)

**核心目标**：建立绝对纯净的开发环境与物理隔离护栏，保障多智能体并发开发的顺利推进。

### Prompt 3.1：双轨隔离舱与基建初始化 (Folder Scaffolding)

* **目的**：利用 Cursor 自动生成物理隔离的单体多包目录结构，配置环境变量模板与防污染索引规则。
* **输入**：读取项目根目录文件 `@README.md` 与 `@docs/schema.md`。
* **输出**：
* 根目录基建：`.cursorignore` 索引防污染配置文件，`.env.example` 密钥模板文件。
* 前端隔离舱：基于 React+Vite 的 `/frontend` 脚手架。
* 后端隔离舱：基于 FastAPI 的 `/backend` 脚手架。


* **🛑 人类干预**：手动配置真实的 `.env` 密钥文件；分别在前后端终端执行“点火测试”，验证开发服务器连通性。


### Prompt 3.2：立宪法 (The `.mdc` Guardrails)

* **目的**：为前后端双线并发开发设立物理边界与最高规则“宪法”，彻底杜绝智能体的越权操作（Scope Creep）与技术栈幻觉。
* **输入**：读取项目根目录核心资产 `@docs/PRD.md`、`@docs/schema.md`、`@docs/UI_BLUEPRINT.md`。
* **输出**：在 `.cursor/rules/` 目录下自动生成两个互不干扰的规则文件：
* `100-frontend.mdc`（锁定前端视野，强制绑定 UI 蓝图与 Mock 数据验证，限用 React+Vite+Tailwind）
* `200-backend.mdc`（锁定后端视野，强制 100% 对齐数据契约，限用 FastAPI，并保持无状态原则）


* **🛑 人类干预**：团队大统筹执行“攻防测试”——故意诱导前端 Agent 去修改后端的端口，验证规则引擎是否成功拦截越权请求。


### Prompt 3.3：造任务机 (The Task Tracker)
* **目的**：将高维度的架构文档降维成颗粒度极高、可执行、可打勾的 Scrum 任务清单。
* **输入**：读取核心资产 `@docs/PRD.md`、`@docs/schema.md`、`@docs/UI_BLUEPRINT.md`。
* **输出**：在根目录生成 `TASK_TRACKER.md`，包含后端主线、前端主线（基于 Mock 开发）、前后端联调合拢、验收底线四个阶段的 Checklists。
* **🛑 人类干预**：将该文件置顶在 IDE 中作为“作战大屏”。严格执行“一小时熔断机制”，任何卡顿超过一小时的 UI/功能必须被无情裁剪，确保核心跑通。
